Hack The Box / Easy / Windows

Legacy

Legacy is a Windows XP host (LEGACY, workgroup HTB) exposing SMB on 139/445 with SMBv1 enabled and SMB message signing disabled. Service detection and Nmap vuln scripts confirmed both MS08-067 (CVE-2008-4250) and MS17-010 (CVE-2017-0143). Vulnerability detection alone is not treated as proof of a SYSTEM session: the retained Metasploit ms08_067_netapi attempt used Automatic Targeting, failed to determine the exact service pack, and created no session, so manual target selection (XP SP2/SP3 with the appropriate NX setting and SMBPIPE=SRVSVC) or a pivot to the MS17-010 path was planned. Proof artifacts for the user and root flags are recorded.

Retired · Authorized laboratory assessment · Reviewed: 2025-12-05

Dylan Senez / D4RKGUNN3R

Legacy SMBv1 on Windows XP, MS08-067 and MS17-010 vulnerability detection, Metasploit target-selection troubleshooting, out-of-support platform

Case overview

Outcome

Confirmed unauthenticated RCE exposure on an out-of-support Windows XP SMBv1 host via MS08-067 and MS17-010; user and root proof artifacts recorded, with the automated exploit attempt left unresolved on automatic target selection in the retained evidence.

Key takeaway

An unpatched Windows XP host running SMBv1 with signing disabled is exposed to multiple wormable, unauthenticated RCE paths; the primary risk is the missing patch state and unsupported platform rather than any single configuration control.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Nmap full TCP scan (139/445, Windows XP) -> netexec SMB profile showing Windows 5.1 x32, signing False, SMBv1 True -> Nmap smb-vuln scripts confirm MS08-067 (CVE-2008-4250) and MS17-010 (CVE-2017-0143) -> Metasploit ms08_067_netapi with Automatic Targeting fails to determine the service pack -> planned manual XP SP2/SP3 selection and SMBPIPE=SRVSVC, or pivot to MS17-010 -> recorded user and root proof artifacts.

1. Reconnaissance — Full TCP scan with service and version detection

Validated · Kali / attacker · EVD-001

Artifact

Nmap full TCP scan output

Command / request

nmap -sVC -p- 198.51.100.10 -T4 --min-rate 5000

Observed result

445/tcp was reported open as microsoft-ds serving Windows XP microsoft-ds. NSE reported smb-security-mode message_signing: disabled and smb2-time: Protocol negotiation failed (SMB2).

Analysis

SMBv1-only negotiation with signing disabled on a Windows XP banner defines the legacy SMB attack surface.

Why this mattered

Establishes the SMB service state and OS family that drive the vulnerability checks.

2. Reconnaissance — SMB protocol profiling with netexec

Validated · Kali / attacker · EVD-002

Artifact

netexec smb output

Command / request

netexec smb 198.51.100.10

Observed result

Reported: Windows 5.1 x32 (name:LEGACY) (domain:legacy) (signing:False) (SMBv1:True). A blank logon appeared to be accepted, but share enumeration with specific usernames failed.

Analysis

The SMBv1 enablement and signing-disabled state are confirmed independently of Nmap; the apparent blank logon did not translate into browsable shares, so it is not treated as access.

Why this mattered

Corroborates the SMB configuration and characterises the authentication behaviour before exploitation.

3. Reconnaissance — SMB vulnerability scanning

Validated · Kali / attacker · EVD-003

Artifact

Nmap SMB vuln script output

Command / request

nmap --script vuln -p445 198.51.100.10

Observed result

smb-vuln-ms08-067: VULNERABLE (CVE-2008-4250) and smb-vuln-ms17-010: VULNERABLE (HIGH).

Analysis

Two unauthenticated remote code execution vulnerabilities are confirmed present; detection alone does not demonstrate a session, so exploitation validation remains required.

Why this mattered

Identifies the concrete RCE paths to pursue for initial access.

4. Exploitation — MS08-067 attempt with Automatic Targeting fails

Validated · Kali / attacker · EVD-004

Artifact

Metasploit ms08_067_netapi output

Command / request

use exploit/windows/smb/ms08_067_netapi ; set RHOSTS 198.51.100.10 ; run

Observed result

The module's Automatic Targeting failed to determine the exact Windows XP service pack and no session was created.

Analysis

Automatic target detection cannot resolve the XP service pack on this host, so the exploit needs a manually selected target variant; the failed attempt is retained rather than treated as exploitation.

Why this mattered

Documents the observed failure and the reason automatic exploitation did not complete.

Findings & remediation

F-1 — Legacy SMBv1 enabled with message signing disabled

High · Validated · 198.51.100.10:445 (Windows XP)

Description

The host negotiates SMBv1 and reports SMB message signing disabled. SMBv1 lacks modern security controls and is susceptible to multiple downgrade and RCE attack chains, and disabled signing permits tampering or relay in certain contexts.

Impact

Increased likelihood of credential relay, man-in-the-middle activity and RCE via legacy exploit paths; combined with Windows XP the risk is severe.

Root cause

An SMBv1-only SMB stack with message signing disabled.

Remediation

  • Disable SMBv1 and enforce SMBv2+ with signing required, upgrade the OS, and restrict SMB exposure to trusted networks.

Validation

  • Confirmed both by Nmap smb-security-mode (message_signing: disabled, SMB2 negotiation failed) and by netexec (signing:False, SMBv1:True).

F-2 — Out-of-support operating system (Windows XP)

High · Validated · 198.51.100.10 (Windows XP)

Description

Service banners and Nmap SMB OS discovery identify the host as Windows XP (Windows 2000 LAN Manager), a platform that no longer receives security updates.

Impact

High likelihood of known, wormable vulnerabilities and no vendor fixes, so every unpatched SMB/RPC flaw remains permanently exploitable.

Root cause

Continued operation of an end-of-support operating system on a network-reachable segment.

Remediation

  • Migrate to a supported Windows release, and segment and strictly limit access until the host is decommissioned.

Validation

  • Nmap smb-os-discovery reported OS: Windows XP (Windows 2000 LAN Manager), NetBIOS name LEGACY, and netexec reported Windows 5.1 x32.

F-3 — MS08-067 remote code execution (confirmed vulnerable)

Critical · Validated · 198.51.100.10:445 (Windows XP)

Description

Nmap reports the system vulnerable to MS08-067 (CVE-2008-4250, CWE-120), a Server service RPC path canonicalization buffer overflow enabling unauthenticated remote code execution.

Impact

Likely full SYSTEM compromise via a crafted RPC request without authentication.

Root cause

Missing MS08-067 patch on the Windows XP Server service.

Remediation

  • Apply the MS08-067 patch or decommission the Windows XP host and disable external SMB exposure.

Validation

  • Nmap smb-vuln-ms08-067 reported VULNERABLE (CVE-2008-4250). Note that the retained Metasploit ms08_067_netapi attempt failed on automatic targeting and created no session, so the vulnerability is confirmed while verified exploitation remains unproven in the retained evidence.

F-4 — MS17-010 EternalBlue (confirmed vulnerable)

Critical · Validated · 198.51.100.10:445 (SMBv1)

Description

Nmap reports the SMBv1 server vulnerable to MS17-010 (CVE-2017-0143 et al., CWE-787), an out-of-bounds write in SMBv1 enabling remote code execution.

Impact

Unauthenticated remote code execution with potential wormable exploitation.

Root cause

Missing MS17-010 patch with SMBv1 still enabled.

Remediation

  • Apply MS17-010 patches or remove SMBv1 and upgrade the OS, and restrict SMB to trusted networks.

Validation

  • Nmap smb-vuln-ms17-010 reported VULNERABLE (HIGH).

Analysis

The machine's risk is an exposed, unpatched legacy SMB/RPC stack on an end-of-support Windows XP host. SMBv1 being enabled and signing disabled are supporting configuration weaknesses, while the actionable vulnerabilities are MS08-067 and MS17-010, both confirmed by Nmap vuln scripts. The retained narrative records the vulnerability confirmations and proof artifacts but leaves the successful exploitation parameters undocumented, so detection and proof claims are kept distinct.

Remediation

  • Apply MS08-067 and MS17-010 patches or decommission the Windows XP host, disable SMBv1 and require SMB message signing, remove external SMB exposure by blocking 445/139 at the network boundary, and migrate to a supported operating system.

Defender perspective

Treat any reachable SMBv1 endpoint as exposed to wormable RCE; detect MS08-067 and MS17-010 exploitation attempts through SMB/RPC traffic anomalies and monitor for out-of-support hosts remaining on the network, prioritizing their patching or isolation.

Detection opportunities

  • Alert on SMBv1 usage and legacy SMB/RPC exploit signatures (MS08-067 Server service path handling, MS17-010 SMB buffer patterns), monitor SMB authentication anomalies, and track end-of-life hosts through asset inventory and authenticated scanning.

Lessons learned

  • Vulnerability confirmation from scanners is not the same as a demonstrated session; pairing version/vuln-script evidence with a verified exploit step keeps findings honest. An out-of-support OS with SMBv1 and signing disabled concentrates multiple unauthenticated RCE paths on one host.

Open questions

  • The retained narrative captures the failed ms08_067_netapi attempt and lists user and root proof artifacts but does not record the exact successful exploit parameters; whether the flags were ultimately retrieved via manual ms08_067 targeting or the MS17-010 path is not verifiable from the retained evidence.

Troubleshooting & success factors

  • The ms08_067_netapi module's Automatic Targeting could not determine the exact Windows XP service pack and produced no session; the intended retry was to select the XP SP2/SP3 English target variant with the appropriate NX setting and set SMBPIPE to SRVSVC, falling back to the MS17-010 path if the host proved unstable.
