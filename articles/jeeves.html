Hack The Box / Medium / Windows

Jeeves

Jeeves is a Windows host exposing IIS on 80, MSRPC on 135, SMB on 445 and a Jetty service on 50000. Enumeration of the Jetty context led to a foothold whose Jenkins workspace and an exfiltrated KeePass database (CEH.kdbx) were recovered. The KeePass master password was cracked offline and the vault exposed a long hexadecimal secret that was used as a Windows credential. A pass-the-hash exchange with the Administrator account produced a SYSTEM-level Windows shell, and the root flag was stored inside an NTFS Alternate Data Stream on the Administrator's desktop.

Retired · Authorized laboratory assessment · Reviewed: 2025-11-10

Dylan Senez / D4RKGUNN3R

IIS/Jetty enumeration, SMB and MSRPC profiling, KeePass (.kdbx) credential recovery, pass-the-hash to Administrator, NTFS Alternate Data Streams

Case overview

Outcome

Administrator-level Windows shell obtained via pass-the-hash; root proof read from an NTFS Alternate Data Stream.

Key takeaway

Credential material handed to a build/CI stack (a KeePass vault and reused high-value secrets) plus an enabled NTLM hash-reuse path let a foothold escalate straight to Administrator, and a flag hidden in an NTFS ADS merely obscured rather than protected the asset.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Nmap (80/135/445/50000) -> Jetty /askjeeves context discovery -> KeePass CEH.kdbx exfiltration and offline master-password crack -> vault secret reused as a Windows credential -> crackmapexec local-auth validation -> pass-the-hash (pth-winexe) as Administrator -> root flag read from hm.txt:root.txt:$DATA ADS.

1. Reconnaissance — Full TCP scan with service detection

Validated · Kali / attacker · EVD-001

Artifact

Nmap full TCP scan output

Command / request

nmap -sV -sC -p- 198.51.100.10 -T4 --min-rate 5000 -oA Je

Observed result

Ports discovered: 80/tcp Microsoft IIS httpd 10.0 (title "Ask Jeeves", TRACE listed as a potentially risky method); 135/tcp Microsoft Windows RPC; 445/tcp microsoft-ds (workgroup WORKGROUP); 65532 filtered tcp ports. Host name JEEVES; clock skew ~5 hours; SMB message signing disabled but not required. A later scan added 50000/tcp serving Jetty 9.4.z-SNAPSHOT.

Analysis

The combination of IIS, MSRPC, SMB and a Java (Jetty) service defines the attack surface. Disabled SMB signing and an exposed Jetty instance are the notable risks; port presence alone is not treated as a finding.

Why this mattered

Establishes the reachable services and versions that drive the rest of the assessment.

2. Reconnaissance — Targeted Jetty scan on 50000/tcp

Validated · Kali / attacker · EVD-002

Artifact

Nmap targeted scan output

Command / request

nmap -sV -sC -p50000 198.51.100.10 -T4 --min-rate 5000 -Pn

Observed result

50000/tcp open http Jetty 9.4.z-SNAPSHOT; http-title "Error 404 Not Found"; http-server-header Jetty(9.4.z-SNAPSHOT).

Analysis

The default 404 indicates a Java webapp with an application context path rather than a bare root; directory and extension brute-forcing is the right next move.

Why this mattered

Confirms a distinct Java application tier to enumerate separately from IIS on port 80.

3. Reconnaissance — Content discovery on the Jetty service

Validated · Kali / attacker · EVD-003

Artifact

feroxbuster output

Command / request

feroxbuster --url http://198.51.100.10:50000/ -w /usr/share/seclists/Discovery/Web-Content/directory-list-2.3-medium.txt

Observed result

Redirects revealed the base context /askjeeves plus /askjeeves/search, /askjeeves/security, /askjeeves/version and /askjeeves/assets (all 302). Stable 404 responses were ~7 KB and were auto-filtered.

Analysis

The dense set of 302 redirects under /askjeeves identifies the real application context; manual review of each redirect target and its cookies is warranted.

Why this mattered

Locates the application context that hosts the build/CI functionality later found to hold credential material.

4. Exploitation — Local-auth credential validation for kohsuke

Validated · Kali / attacker · EVD-004

Artifact

crackmapexec output

Command / request

crackmapexec smb 198.51.100.10 -u kohsuke -p '[REDACTED]' --local-auth

Observed result

Recorded in the retained notes as a non-intrusive single-user validation attempt against the identified account name.

Analysis

kohsuke is the account associated with the Jenkins-hosted build tooling; validating its credential is a natural step once credential material had been collected.

Why this mattered

Tests whether recovered credential material grants an authenticated Windows foothold.

5. Credential Access — Exfiltrate and crack the KeePass database (CEH.kdbx)

Validated · Kali / attacker · EVD-005

Artifact

CEH.kdbx, CEH.hash, john output

Command / request

nc -lp 1336 > CEH.kdbx ; keepass2john CEH.kdbx > CEH.hash ; john --wordlist=/usr/share/wordlists/rockyou.txt CEH.hash

Observed result

The vault located at C:\Users\kohsuke\Documents\CEH.kdbx was transferred out over a listener, converted with keepass2john, and its master password was recovered by John the Ripper (value redacted).

Analysis

Offline cracking of the vault master password is feasible because the password space is covered by a common wordlist. This is the pivotal step that exposes every secret the vault protects.

Why this mattered

The vault master password unlocks the credential store that drives escalation.

6. Credential Access — Extract the harvested vault entry

Validated · Kali / attacker · EVD-006

Artifact

KeePass entry "Backup stuff"

Command / request

(manual review of the unlocked KeePass vault)

Observed result

Entry titled "Backup stuff" contained a long hexadecimal password value (redacted), with a placeholder example URL and an expiry date of 2017-09-18.

Analysis

The value's 40+ hex character shape is inconsistent with a typical cleartext login; it is more consistent with an NTLM (NT) hash, so pass-the-hash is the correct interpretation rather than plaintext authentication.

Why this mattered

Determines how the recovered secret should be used against Windows authentication.

7. Privilege Escalation — Pass-the-hash to Administrator

Validated · Kali / attacker · EVD-007

Artifact

pth-winexe session

Command / request

pth-winexe -U jeeves/Administrator%[REDACTED] //198.51.100.10 cmd

Observed result

A Windows command shell (Microsoft Windows [Version 10.0.10586]) at C:\Windows\system32 was returned as Administrator.

Analysis

Because NTLM authentication accepts the hash directly, knowledge of the NT hash alone is sufficient for authentication; no plaintext cracking is required. This is the escalation to Administrator.

Why this mattered

Demonstrates that the harvested hash is a directly usable authentication credential.

8. Proof — Read the root flag from an NTFS Alternate Data Stream

Validated · Kali / attacker (Administrator shell) · EVD-008

Artifact

hm.txt:root.txt:$DATA

Command / request

cd C:\Users\Administrator\Desktop ; dir /R ; more < hm.txt:root.txt:$DATA

Observed result

The desktop file hm.txt carried a hidden stream hm.txt:root.txt:$DATA; reading that stream returned the root flag (value redacted).

Analysis

Alternate Data Streams hide content from a normal directory listing but provide no protection against reading once the stream name is known; the flag was recovered in cleartext.

Why this mattered

Completes the proof chain by retrieving the Administrator-level flag.

Findings & remediation

F-1 — Weak master password on a reachable KeePass credential vault

High · Validated · C:\Users\kohsuke\Documents\CEH.kdbx (Windows host JEEVES)

Description

A KeePass database reachable from the build/CI foothold used a master password that was recovered offline with a common wordlist. The unlocked vault disclosed long-lived credential material.

Impact

Any party with read access to the vault could recover all protected secrets, enabling further authentication as other accounts.

Root cause

A weak, dictionary-crackable master password protecting a credential store that was accessible from a low-trust foothold on the build host.

Remediation

  • Enforce a strong, high-entropy master password for credential vaults, store vaults off build hosts that can be reached from a foothold, and rotate any secret the vault contained.

Validation

  • The vault was exfiltrated, converted with keepass2john, and its master password recovered with John the Ripper; the vault then opened and disclosed its entries.

F-2 — NTLM hash reuse enabling pass-the-hash to Administrator

High · Validated · Administrator account on Windows host JEEVES

Description

A hexadecimal secret recovered from the vault functioned as the Administrator NTLM hash and was accepted directly by NTLM authentication, yielding a SYSTEM-context Windows shell.

Impact

Full administrative control of the host without knowledge of any plaintext password.

Root cause

NTLM authentication permits hash-based logon, and the Administrator NT hash was both harvested and usable from the attacker's position.

Remediation

  • Disable NTLM where possible, restrict and monitor pass-the-hash tooling, apply the principle of least privilege to account credentials, and rotate the Administrator hash after exposure.

Validation

  • pth-winexe authenticated with the harvested hash and returned a working Administrator command shell (Windows 10.0.10586).

F-3 — Sensitive proof stored in an NTFS Alternate Data Stream

Low · Validated · C:\Users\Administrator\Desktop\hm.txt

Description

The Administrator-level flag was concealed inside the NTFS Alternate Data Stream hm.txt:root.txt:$DATA.

Impact

Minimal. ADS provides no confidentiality; it only hides content from casual directory listings and was trivially read once located.

Root cause

Treating an Alternate Data Stream as a security control for sensitive data.

Remediation

  • Do not rely on Alternate Data Streams to protect sensitive content; store secrets in managed secret stores with proper access controls and monitoring.

Validation

  • Listing with dir /R revealed the stream, and more < hm.txt:root.txt:$DATA read the flag in cleartext.

Analysis

The machine's risk concentrates in credential handling rather than a single memory-corruption bug: a KeePass vault was reachable from a build workspace and its master password was weak enough to crack offline, and the recovered hex secret corresponded to an NTLM hash usable for pass-the-hash against Administrator. Port surfaces themselves (TRACE on IIS, disabled SMB signing) are supporting context, not standalone findings.

Remediation

  • Store secrets in a vault whose master password meets strength requirements and is not reusable, avoid placing vaults or CI credentials on build hosts that are reachable from an initial foothold, disable NTLM authentication where possible and enforce SMB signing, and never rely on NTFS Alternate Data Streams to protect sensitive files.

Defender perspective

Detect offline-cracking preparation by watching for keepass2john-style tooling and vault file reads on build hosts, alert on NTLM logons to the local Administrator account from non-admin workstations, and enable SMB signing plus restrict NTLM to break hash-reuse paths.

Detection opportunities

  • Monitor for pth-winexe/impacket-style authentication patterns against Administrator, unexpected reads of .kdbx files under user or CI workspaces, and access to Alternate Data Streams on desktop files; enable SMB signing and audit Windows credential-reuse events.

Lessons learned

  • CI and build infrastructure frequently holds the highest-value secrets on a host; a folder-scoped foothold is only as strong as the credential material reachable from that folder, and a weak vault master password collapses the whole chain.

Open questions

  • The precise initial-access primitive that produced the foothold shell is not captured verbatim in the retained notes; the source records the Jenkins workspace context (C:\Users\Administrator\.jenkins\workspace\nec) and the exfiltrated vault but not the exact request that granted code execution.

Troubleshooting & success factors

  • The John the Ripper crack against the KeePass hash required the rockyou wordlist; the vault secret was a long hex string that did not behave as a cleartext WinRM password and was ultimately validated as an NTLM NT hash for pass-the-hash.
