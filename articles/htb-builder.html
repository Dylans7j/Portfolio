08 / Findings & remediation

F-01 — Vulnerable Jenkins deployment

Severity: High

The Jenkins deployment permitted sensitive file-read behavior that exposed controller data.

  • Upgrade Jenkins to a fixed release.
  • Restrict CLI exposure where not required.
  • Limit Jenkins access to trusted administrative networks.

F-02 — Recoverable Jenkins password

Severity: High

A recovered password hash was susceptible to offline cracking.

  • Require strong, unique passwords.
  • Use MFA or centralized identity where supported.
  • Rotate credentials exposed through application artifacts.

F-03 — Excessive administrative capability

Severity: High

The compromised Jenkins account could access host-impacting administrative functionality.

  • Restrict administrative scripting permissions.
  • Review role assignments and apply least privilege.

F-04 — Privileged SSH credential stored in Jenkins

Severity: Critical

Jenkins stored SSH key material capable of privileged host authentication.

  • Do not store root-equivalent SSH keys in CI/CD systems.
  • Use scoped service accounts.
  • Rotate exposed keys and audit dependent systems.
  • Prefer short-lived credentials where possible.

10 / Lessons learned

  • CI/CD systems are high-value targets because they centralize code, credentials, execution, and administration.
  • Application-layer file read can become credential compromise when sensitive artifacts are readable.
  • Administrative scripting features greatly increase blast radius after compromise.
  • Storing privileged SSH credentials in Jenkins can collapse application compromise into host compromise.
  • Evidence and remediation should be documented alongside the attack path.
